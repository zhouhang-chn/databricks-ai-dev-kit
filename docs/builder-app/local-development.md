# Local Development

The fastest path is `scripts/start_local.sh`, which provisions Lakebase, creates `.env.local`, installs dependencies, installs skills, validates database access, and starts both servers.

## Prerequisites

- Python 3.11+
- Node.js 18+
- `uv`
- `pnpm`
- Databricks CLI 0.287.0+
- A Databricks CLI profile with access to the target workspace
- Lakebase Autoscale enabled in the workspace if using the default local flow

## One-command Start

```bash
cd databricks-builder-app
./scripts/start_local.sh --profile <profile>
```

Useful options:

```bash
./scripts/start_local.sh --profile <profile> --skip-lakebase
./scripts/start_local.sh --profile <profile> --force-env
./scripts/start_local.sh --profile <profile> --force-install
./scripts/start_local.sh --profile <profile> --lakebase-id my-builder-db
```

The script starts:

- Backend: `http://localhost:8000`
- Frontend: `http://localhost:3000`
- API docs: `http://localhost:8000/docs`

## Manual Start

Use this when you need tighter control over each process.

```bash
cd databricks-builder-app
uv sync
uv pip install -e ../databricks-tools-core -e ../databricks-mcp-server
```

Create or update `.env.local`:

```bash
DATABRICKS_HOST=https://<workspace-host>
DATABRICKS_TOKEN=<token>
LAKEBASE_ENDPOINT=projects/<lakebase-project>/branches/production/endpoints/primary
LAKEBASE_DATABASE_NAME=databricks_postgres
ENABLED_SKILLS=
SKILLS_ONLY_MODE=false
ENV=development
PROJECTS_BASE_DIR=./projects
CLAUDE_CODE_STREAM_CLOSE_TIMEOUT=3600000
MLFLOW_TRACKING_URI=databricks
MLFLOW_EXPERIMENT_NAME=/Workspace/Users/<user>/builder_app_local_traces
```

Install frontend dependencies and run the Vite dev server:

```bash
cd databricks-builder-app/client
pnpm install
pnpm dev
```

In another shell, run the backend:

```bash
cd databricks-builder-app
uv run uvicorn server.app:app --reload --port 8000 --reload-dir server
```

Vite proxies `/api` to `http://127.0.0.1:8000`.

## Service Checks

Before frontend or browser tests, verify both services are reachable:

```bash
curl -fsS http://127.0.0.1:8000/api/config/health
curl -fsS http://127.0.0.1:3000/
```

If you use a production preview server instead of Vite dev, check that port instead:

```bash
cd databricks-builder-app/client
pnpm build
pnpm preview --host 127.0.0.1 --port 4173
curl -fsS http://127.0.0.1:4173/
```

`pnpm preview` only serves the built frontend. It does not replace the production FastAPI static-file path, so end-to-end API flows should use Vite dev with the `/api` proxy or run the backend against `client/out`.

## Frontend Checks

```bash
cd databricks-builder-app/client
pnpm lint
pnpm build:typecheck
```

## Backend Checks

There is no dedicated builder-app test command documented in the repo today. For syntax and import checks during local work:

```bash
cd databricks-builder-app
uv run python -m compileall server
uv run ruff check server
```

For changes that touch shared tool behavior, also run the relevant sibling package tests:

```bash
cd databricks-tools-core
uv run pytest tests/unit -v

cd ../databricks-mcp-server
uv run pytest tests -v
```

## Local Environment Variables

| Variable | Required | Purpose |
|----------|----------|---------|
| `ENV` | Recommended | `development` enables local CORS and dev auth fallback |
| `DATABRICKS_HOST` | Yes | Workspace URL without trailing slash |
| `DATABRICKS_TOKEN` | Yes locally | Token used for Databricks tools and FMAPI auth in development |
| `LAKEBASE_PG_URL` | One DB mode | Static PostgreSQL URL with password |
| `LAKEBASE_ENDPOINT` | One DB mode | Lakebase Autoscale endpoint resource name |
| `LAKEBASE_INSTANCE_NAME` | One DB mode | Provisioned Lakebase instance name |
| `LAKEBASE_DATABASE_NAME` | Dynamic DB modes | Database name, usually `databricks_postgres` |
| `LAKEBASE_SCHEMA_NAME` | Optional | PostgreSQL schema, default `builder_app` |
| `PROJECTS_BASE_DIR` | Optional | Local project workspace root, default `./projects` |
| `ENABLED_SKILLS` | Optional | Comma-separated app-level skill allowlist; empty means copy all available skills |
| `SKILLS_ONLY_MODE` | Optional | Preserved for compatibility with skill loading code |
| `LLM_PROVIDER` | Optional | Generated by local scripts for app configuration compatibility |
| `DATABRICKS_MODEL` | Optional | Generated Databricks model setting for app configuration compatibility |
| `DATABRICKS_MODEL_MINI` | Optional | Generated small-model setting for app configuration compatibility |
| `ANTHROPIC_MODEL` | Optional | Model name sent to the Claude subprocess; defaults in code if unset |
| `ANTHROPIC_MODEL_MINI` | Optional | Model name used by title generation; falls back to `ANTHROPIC_MODEL` |
| `CLAUDE_CODE_STREAM_CLOSE_TIMEOUT` | Optional | Claude Code stream timeout in milliseconds; script uses `3600000` |
| `MLFLOW_TRACKING_URI` | Optional | Usually `databricks` |
| `MLFLOW_EXPERIMENT_NAME` | Optional | Enables MLflow tracing when set |

## Common Local Issues

### Backend starts but project APIs fail

Check the database mode. The backend logs one of the supported configurations on startup. If using Lakebase OAuth mode, make sure `LAKEBASE_ENDPOINT` or `LAKEBASE_INSTANCE_NAME` is paired with `LAKEBASE_DATABASE_NAME`.

### Browser cannot call the API

Confirm `ENV=development`, backend is on `127.0.0.1:8000`, and the frontend dev server is on a CORS-allowed origin. The app allows `localhost:3000`, `localhost:3001`, and `localhost:5173` in development.

### Skills are missing

Check all three locations:

- `databricks-builder-app/.claude/skills`
- `databricks-skills/`
- `databricks-builder-app/skills`

Then reload a project from the Skills Explorer or restart the backend to repopulate the app cache.

### Agent tool calls fail with auth errors

Check `DATABRICKS_HOST` and `DATABRICKS_TOKEN` in `.env.local`, then call:

```bash
databricks current-user me --profile <profile>
```

The local script refreshes `.env.local` from the profile token on each run unless the file is regenerated manually.
