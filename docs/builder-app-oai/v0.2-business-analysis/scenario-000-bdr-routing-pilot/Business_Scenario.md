## 1. Scenario Name

**ML-Based BDR Routing Optimization Pilot**

## 2. Business Background

BDRs are responsible for visiting assigned POCs in their monthly visit base. Each POC has an expected visit frequency based on business priority and sales execution rules.

Currently, many BDRs rely on their own experience to arrange visit routes. This may lead to incomplete coverage, poor visit-frequency adherence, inefficient travel, uneven daily workload, and inconsistent execution quality.

To improve BDR visit efficiency, the business is piloting an **ML-generated routing and visit-plan program**. The model generates optimized visit plans for selected pilot BDRs. The analysis needs to evaluate whether this ML-based plan performs better than the traditional self-planned approach.

## 3. Business Goal

The goal is to determine whether the ML-based routing plan is strong enough to support **BU-level or national rollout**.

The core business question is:

```text
Does the ML-generated routing plan improve BDR visit effectiveness and efficiency compared with BDRs’ own non-ML planning?
```

## 4. Intervention

The intervention is:

```text
ML-generated monthly routing / visit plan for test-group BDRs.
```

The non-intervention baseline is:

```text
BDR self-planned / non-ML routing plan.
```

## 6. Core Metrics

### 6.1 Visit Base Coverage

Measures whether POCs in the BDR’s visit base were visited during the month.

```text
visit_base_coverage_rate
= visited POCs in visit base / total POCs in visit base
```

POC-level rule:

```text
vb_adhere = 1 if monthly POC visit count > 0
```

### 6.2 Visit Frequency Adherence

Measures whether the actual visit count matches the required visit frequency in the visit base.

```text
visit_frequency_adherence_rate
= POCs whose actual visit count equals required visit frequency
  / total POCs in visit base
```

POC-level rule:

```text
vf_adhere = 1 if actual monthly visit count = required visit frequency
```

### 6.3 Visit Time

Measures how long BDRs stay at POCs for business activity.

Typical metrics:

```text
- total visit time
- average visit time per visit
- visit time per working day
```

### 6.4 Travel / Commute Time

Measures how long BDRs spend moving between POCs.

Typical metrics:

```text
- total travel time
- travel time per working day
- travel time per visit
```

### 6.5 Travel Distance

Supports travel-time analysis using GPS distance between visited POCs.

Typical metrics:

```text
- total travel distance
- travel distance per working day
- travel distance per visit
```

### 6.6 Visits per Working Day per BDR

Measures daily execution productivity.

Working day definition:

```text
A BDR-day is counted as a working day if the BDR has at least one valid visit on that day.
```

Metric:

```text
avg_valid_visits_per_working_day
= total valid visits / valid working days
```

## 7. Comparison Design

### Comparison 1: Test Group Pre-Post

```text
Test-group BDRs in pilot month with ML plan
vs
same test-group BDRs in previous month without ML plan
```

Purpose:

```text
Measure whether pilot BDRs improved after using the ML plan.
```

Limitation:

```text
This alone cannot fully separate ML impact from seasonality, holidays, market changes, or management attention.
```

### Comparison 2: Test vs Control / Delta Comparison

```text
Test group delta = test pilot month KPI - test previous month KPI

Control group delta = control pilot month KPI - control previous month KPI

Estimated ML impact = test group delta - control group delta
```

Purpose:

```text
Evaluate whether the test group improved more than comparable non-ML BDRs.
```

This is the stronger evidence for rollout.

## 8. Success Hypothesis

The ML-based routing plan is successful if test-group BDRs show stronger improvement than the control group on key effectiveness and efficiency metrics.

Expected improvement pattern:

```text
- visit base coverage improves or at least does not decline
- visit frequency adherence improves
- visit time remains stable or improves
- travel time decreases
- travel distance decreases
- valid visits per working day increases
```

The strongest business claim would be:

```text
ML routing helps BDRs cover the right POCs with better frequency adherence while reducing travel burden and improving daily visit productivity.
```

## 10. Answer-Shaping Rules

Highest-priority metrics:

```text
- visit_base_coverage_rate
- visit_frequency_adherence_rate
```

Guardrail metrics:

```text
- travel_commute_time
- travel_distance
- avg_valid_visits_per_working_day
- visit_time
```

Answer rules:

```text
1. Coverage and frequency adherence take priority over pure productivity gains.
2. Travel-time or travel-distance reduction is positive only if coverage and frequency adherence do not materially deteriorate.
3. Higher valid visits per working day is positive only if visit effectiveness does not deteriorate.
4. Do not call the result causal unless control-group comparability, date-window alignment, and core data-quality checks hold.
5. If comparability is not validated, use cautious language such as "estimated impact" or "consistent with improvement" rather than "caused by ML routing."
6. A rollout-positive answer requires improvement or no deterioration on the highest-priority metrics plus no material guardrail regression.
7. If priority metrics and guardrail metrics disagree, recommend limited rollout, further validation, or targeted follow-up rather than broad rollout.
8. If frequency-adherence semantics are unresolved, state whether exact-match or minimum-frequency compliance was used.
```
